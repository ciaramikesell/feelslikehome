# Hosted-migration and rollout review

Status is **awaiting separate approval**. The hosted catalog was not queried during isolated QA. No hosted migration, writer credential, deployment or flag change was made. The repository opts the PR branch out of automatic Vercel Git deployments. The target project's catalog, GoTrue confirmation settings and deployment networking are unverified. The [read-only preflight SQL](proposed-preflight.sql) is attached for the authorized operator. Run it in the intended project only at the approved stage and attach the output to the rollout review.

## Staged sequence

1. **Before any migration**, confirm the target app/account/search schema, non-deferrable membership foreign keys, unique participant priority key, auth signup trigger order, and deployed `postgres` privileges to read and lock `auth.users` and create the trigger. Run the read-only checks for the current platform role. Before provisioning, the writer rows are empty and the rest of the preflight is runnable. Confirm the Auth project requires email confirmation and allows the fixed callback on the intended origin. A project with email autoconfirm would not provide the inbox proof assumed by this design.
2. **Before provisioning the writer**, confirm which managed principal can create the login and satisfy the zero-membership preflight. PostgreSQL 16 can grant an administering non-superuser membership on newly created roles. The migration rejects role membership and privileged attributes. If the platform cannot provision the role with these properties, return for review. Check effective PUBLIC grants and the absence of an earlier public transfer function. Use the [writer provisioning SQL](proposed-provision-writer.sql) with a password provided out of band.
3. **Prove network and session behavior** in a separately approved isolated preview project before considering Production. Start with a direct PostgreSQL endpoint if the deployment can reach its address family and network policy permits it. A session pooler is viable only if a connection as the writer reports `session_user = 'flh_guest_writer'` and verifies the endpoint certificate. Reject paths that expose a shared login or substitute `SET ROLE` for the actual login. The local rehearsal proved the restricted login over verified TLS. It does not establish Vercel-to-hosted Postgres connectivity. The writer connection pool is capped at two per process and the role at five connections. Review preview concurrency and cold starts before rollout.
4. **With the guest flag off**, apply the reviewed [implementation migration](../../supabase/migrations/2026-11-18-guest-onboarding-transfer.sql) only in the approved target. It includes the additional owner autosave guard. Verify private function grants, signup trigger, compatible schema, and rollback rehearsal. Keep the guest writer URL server-only, set the exact app origin, and keep guest onboarding off until QA is approved. Separately approve preview activation and run the browser/device checklist. When considering Production later, account for cached older app code and drain old sessions before exposing the transfer path.
5. **Rollback app first**, disabling the feature and stopping new guest starts. Give in-flight writes time to settle, then run the reviewed [disable SQL](proposed-disable.sql) to remove the capture trigger and revoke the writer path. Receipts, account data, and the guarded owner autosave function stay available. Remove or rotate the server-only writer credential through the approved secret process. Existing and unsaved drafts remain on the device for their storage lifetime.

## Configuration

`FLH_GUEST_ONBOARDING=on` must be paired with an exact `FLH_GUEST_APP_ORIGIN` and a server-only `FLH_GUEST_WRITER_DATABASE_URL`. Use an HTTPS origin outside local loopback. Supply `FLH_GUEST_WRITER_CA` only when a private trust root is required. The writer always requires certificate verification. Existing authenticated V3 and invitation flags are independent.
